## 1. Введение

**AI Meal Planner** — это веб-приложение для автоматического формирования персонализированных недельных планов питания.  
Система учитывает цели пользователя (похудение, набор массы, поддержание формы), предпочтения, аллергии и бюджет.  
Результатом является готовый план на неделю с рецептами и списком покупок.

**Цель разработки:**  
Обеспечить пользователей простым инструментом для планирования питания с использованием алгоритмов персонализации и оптимизации продуктовой корзины.

## 3. Функциональные требования

### 3.1 Пользовательские функции
1. Регистрация, вход и редактирование профиля.
2. Ввод данных: возраст, рост, вес, уровень активности, цель, бюджет, аллергии и предпочтения.
3. Генерация недельного плана питания (7 дней, 3 приёма пищи).
4. Просмотр рецептов с ингредиентами, шагами и питательной ценностью.
5. Редактирование плана — замена блюд вручную.
6. Формирование и экспорт списка покупок (CSV/PDF/печать).
7. Хранение истории планов и возможность повторного использования.
8. Возможность фильтрации блюд по типу диеты (вегетарианская, безглютеновая и т.п.).

### 3.2 Административные функции
1. Управление базой рецептов и ингредиентов.
2. Импорт/экспорт данных рецептов в формате CSV.
3. Редактирование тегов, категорий и пищевой информации.
4. Просмотр статистики использования системы.

## 4. Нефункциональные требования

| Категория | Требование |
|------------|-------------|
| **Производительность** | Генерация недельного плана — не более 5 секунд (асинхронно). |
| **Надёжность** | Данные сохраняются при одновременных обращениях нескольких пользователей. |
| **Доступность** | API должно быть доступно 99,5% времени. |
| **Масштабируемость** | Поддержка горизонтального масштабирования backend и ML-сервисов. |
| **Безопасность** | Использование HTTPS и JWT, хеширование паролей, валидация всех входных данных. |
| **Юзабилити** | Время обучения пользователя — не более 5 минут, интуитивный интерфейс. |
| **Хранимые данные** | Все данные сохраняются в PostgreSQL; изображения — в S3-хранилище. |
| **Адаптивность** | Интерфейс должен корректно отображаться на устройствах шириной от 360px. |
| **Модульность** | Кодовая база разделена на независимые компоненты (Frontend / Backend / ML / DB). |

## 6. Архитектурные принципы

1. **Модульность** — разделение на независимые компоненты: Frontend, Backend, ML-сервис, БД.  
2. **Асинхронность** — длительные операции (генерация плана, импорт рецептов) выполняются через очередь задач (Celery + Redis).  
3. **Микросервисный подход** — ML-сервис для персонализации отделён от основной логики.  
4. **REST API** — структурированные endpoints, обмен данными в формате JSON, документирование через Swagger/OpenAPI.  
5. **CI/CD** — автоматическая сборка и деплой через GitHub Actions.  
6. **Контейнеризация** — использование Docker для унификации окружения.  
7. **Observability** — логирование (ELK или Loki), мониторинг (Prometheus + Grafana), отслеживание ошибок (Sentry).  
8. **Security by Design** — HTTPS, JWT, фильтрация данных, ограничение прав доступа.  
9. **Scalability First** — возможность горизонтального масштабирования без изменения бизнес-логики.  
10. **API Versioning** — поддержка версий (v1, v2) для обратной совместимости.
