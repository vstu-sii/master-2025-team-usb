# 3. UX сценарии — AI Meal Planner

---

## **UC-1: Регистрация пользователя (Login via Google)**

### Цель

Пользователь заходит в приложение и авторизуется через Google OAuth.

### Happy Path (основной сценарий)

| Шаг | Действие пользователя                | Система / UI                                           |
| --- | ------------------------------------ | ------------------------------------------------------ |
| 1   | Открывает страницу Login             | Отображается форма с кнопкой “Войти через Google”      |
| 2   | Нажимает кнопку “Войти через Google” | Переход на OAuth страницу Google                       |
| 3   | Подтверждает доступ                  | Возврат в приложение, система создаёт запись в `users` |
| 4   | Перенаправление на Dashboard         | Приветствие: “Привет, [имя]!”                          |

### Alternative Flow (AF-3.2)

- **На шаге 2:** пользователь отменяет авторизацию.
  → UI показывает уведомление: “Авторизация отменена”.

### Error Scenario (E-3.3)

- **На шаге 3:** OAuth-сервис недоступен.
  → UI показывает модальное окно: “Ошибка подключения к Google. Попробуйте позже.”

## **UC-2: Генерация плана питания**

### Цель

Пользователь создаёт новый персонализированный план питания.

### Happy Path

| Шаг | Действие                                                        | Система / UI                                     |
| --- | --------------------------------------------------------------- | ------------------------------------------------ |
| 1   | На Dashboard нажимает “Создать новый план”                      | Переход на страницу формы                        |
| 2   | Заполняет поля (goal, calories, budget, preferences, allergies) | Валидация формы в реальном времени               |
| 3   | Нажимает “Сгенерировать”                                        | Отправка JSON на API `/generate`                 |
| 4   | Состояние “Загрузка” (spinner)                                  | Отображается сообщение “Формируем ваш план...”   |
| 5   | LLM возвращает weekly_plan                                      | Система сохраняет в `meal_plans` и `meals`       |
| 6   | Переход на экран “View Plan”                                    | Пользователь видит сгенерированные блюда по дням |

### Alternative Flow (AF-2.3)

- **На шаге 3:** поля `preferences` или `allergies` пустые.
  → API автоматически заменяет на `"отсутствуют"` (показать подсказку).

### Error Scenario (E-2.3)

- **На шаге 3:** `calories` < 1000 или > 6000 → валидация.
  → UI подсвечивает ошибку “Калорийность от 1000 до 6000”.

## **UC-3: Замена блюда**

### Цель

Пользователь заменяет блюдо в существующем плане через LLM.

### Happy Path

| Шаг | Действие                                                  | Система / UI                         |
| --- | --------------------------------------------------------- | ------------------------------------ |
| 1   | В “View Plan” нажимает “Заменить блюдо”                   | Открывается модальное окно           |
| 2   | Вводит причину замены (например, “не люблю грибы”)        | Поле опционально                     |
| 3   | Нажимает “Подобрать альтернативу”                         | Отправка запроса LLM `/replace_dish` |
| 4   | Отображаются 3-5 вариантов блюд                           | Пользователь выбирает одно           |
| 5   | Система обновляет `meals` и пересчитывает `daily_summary` | UI обновляется без перезагрузки      |

### Alternative Flow (AF-3.3)

- **На шаге 3:** пользователь оставляет поле “причина” пустым.
  → LLM использует контекст предыдущего блюда.

### Error Scenario (E-3.4)

- **На шаге 3:** LLM возвращает пустой список.
  → UI показывает сообщение: “Не удалось подобрать альтернативу. Попробуйте снова.”

---

## **UC-4: Просмотр сохранённых планов**

### Цель

Пользователь просматривает и открывает ранее созданные планы.

### Happy Path

| Шаг | Действие                     | Система / UI                 |
| --- | ---------------------------- | ---------------------------- |
| 1   | Переходит в “Мои планы”      | Отображается список карточек |
| 2   | Применяет фильтр “Похудение” | Список обновляется           |
| 3   | Кликает на карточку плана    | Открывается “View Plan”      |

### Alternative Flow (AF-4.1)

- **На шаге 1:** список пуст.
  → Отображается заглушка “Создайте первый план!” + кнопка “Создать”.

### Error Scenario (E-4.3)

- **На шаге 3:** план не найден (удалён).
  → UI показывает “План недоступен” и возвращает на Dashboard.

---

## **UC-5: Генерация списка покупок**

### Цель

Пользователь получает список ингредиентов по текущему плану.

### Happy Path

| Шаг | Действие                                     | Система / UI                        |
| --- | -------------------------------------------- | ----------------------------------- |
| 1   | В “View Plan” нажимает “Список покупок”      | Открывается экран Shopping List     |
| 2   | Система группирует ингредиенты по категориям | UI показывает чекбоксы              |
| 3   | Пользователь отмечает купленные позиции      | Сумма автоматически пересчитывается |
| 4   | Нажимает “Экспорт PDF”                       | Генерация файла и скачивание        |

### Alternative Flow (AF-5.3)

- **На шаге 3:** пользователь снимает все галочки.
  → Появляется кнопка “Пересчитать заново”.

### Error Scenario (E-5.4)

- **На шаге 4:** отсутствуют ингредиенты (старый план).
  → Сообщение “Нет данных для экспорта”.
