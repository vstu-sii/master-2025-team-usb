## Введение

Данный документ описывает **Definition of Ready (DoR) для задач** и **Definition of Done (DoD) для функций** проекта **AI Meal Planner**.  
Цель документа — установить чёткие критерии готовности задач к выполнению и завершённости функций, определить метрики успеха продукта и KPI для каждого спринта.  
Это помогает команде контролировать прогресс, снижает риск недопонимания и обеспечивает прозрачность выполнения проекта.

---

## 1. Definition of Ready (DoR) для задач

**Цель:** убедиться, что задачи готовы к выполнению в спринте.  

**Критерии DoR для задач AI Meal Planner:**
1. Чёткое описание задачи — что нужно сделать, какие входные и выходные данные.  
2. Приоритет задачи указан — высокий/средний/низкий.  
3. Зависимости определены — задача не стартует без необходимых результатов предыдущих спринтов.  
4. Оценка сложности и времени — примерное количество часов/дней.  
5. Необходимые ресурсы и доступ к данным — доступ к БД, API, тестовым данным, инструментам разработки.  
6. Метрики успеха — определены критерии, по которым задача считается завершённой.  

---

## 2. Definition of Done (DoD) для функций

**Цель:** убедиться, что функциональность завершена и готова к использованию.  

**Критерии DoD для функций AI Meal Planner:**
1. Функция реализована и интегрирована в систему.  
2. Проходит юнит-тесты и интеграционные тесты.  
3. Соответствует требованиям MVP и функциональным спецификациям.  
4. Протестирована с точки зрения UX и удобства интерфейса.  
5. Документирована: описание функции, API, алгоритмы, ограничения.  
6. Производительность соответствует метрикам (например, генерация плана ≤5 сек).  
7. Проведен walkthrough функции с командой и ментором, получен ✅.  

---

## 3. Метрики успеха продукта

| Метрика | Цель | Метод измерения |
|---------|------|----------------|
| Время генерации плана | ≤ 5 секунд | Тестирование API на разных профилях |
| Корректность плана | 100% соответствие требованиям пользователя | Сравнение с тестовыми сценариями |
| Удобство интерфейса | Средняя оценка ≥4/5 | Анкетирование и UX-тестирование |
| Точность рекомендаций AI | ≥80% соответствие предпочтениям | Сравнение истории выборов пользователя с предложениями AI |
| Стабильность системы | 99% uptime | Мониторинг сервера и логирование |

## 4. KPI для каждого спринта

| Спринт | KPI |
|--------|-----|
| Sprint 1 — Артефакты инициации | Документация подготовлена, Use Cases утверждены, Definition of Ready согласованы |
| Sprint 2 — AI Architecture Design Sprint | Архитектура согласована, структура БД и базовый план API готовы |
| Sprint 3 — Прототипирование MVP | MVP-прототип с API, базой данных и AI-моделью запущен |
| Sprint 4 — Production-Ready Infrastructure | CI/CD настроен, контейнеризация завершена, мониторинг работает |
| Sprint 5 — Тестирование и сбор метрик | Тесты пройдены, показатели производительности и UX собраны |
| Sprint 6 — Demo Day | Успешная демонстрация продукта и презентация метрик |
| Sprint 7 — Рецензирование проектов | Документация и рекомендации подготовлены |
