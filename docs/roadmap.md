## 1. Введение

Данный документ представляет **дорожную карту проекта AI Meal Planner**, адаптированную под 4-месячный срок. Спринты распределены по неделям с учётом зависимостей задач, приоритетов MVP и KPI. Отражено текущее состояние выполнения проекта.

---

## 2. Спринты и задачи

| Спринт | Недели | Основные задачи | Результат |
|--------|--------|----------------|------------|
| **Sprint 1 — Артефакты инициации** | 1 | - Определение всех deliverables<br>- Use Cases, функциональные и нефункциональные требования<br>- Метрики производительности и архитектурные принципы | Полный пакет исходной документации для проекта |
| **Sprint 2 — AI Architecture Design Sprint** | 2-3 | - Проектирование backend и frontend<br>- Структура БД (пользователи, рецепты, планы, покупки)<br>- Архитектура AI-модуля<br>- План API и инфраструктуры<br>- Ролевое распределение задач | Архитектура системы согласована, структура БД и базовый план API готовы |
| **Sprint 3 — Прототипирование MVP** | 4-5 | - Реализация базового API и базы данных<br>- Подключение baseline AI-модели для генерации планов<br>- Отображение результатов на интерфейсе<br>- Проверка базового функционала | Цель: MVP-прототип с API, БД и AI-моделью запущен и работает |
| **Sprint 4 — Production-Ready Infrastructure** | 6 | - Контейнеризация сервисов (Docker)<br>- Настройка CI/CD (GitHub Actions)<br>- Мониторинг и логирование (Prometheus, Grafana, Sentry)<br>- Автоматизированное тестирование | Цель: CI/CD настроен, контейнеризация завершена, мониторинг работает |
| **Sprint 5 — Тестирование и сбор метрик** | 7-8 | - Юнит и интеграционные тесты<br>- Проверка производительности AI-модуля и API (≤5 сек)<br>- Сбор UX-метрик<br>- Оптимизация кода и алгоритмов | Цель: Тесты пройдены, показатели производительности и UX собраны |
| **Sprint 6 — Demo Day** | 9 | - Подготовка презентации архитектуры и функциональности<br>- Демонстрация персонализированных планов<br>- Представление метрик производительности и UX<br>- Ответы на вопросы экспертов | Цель: Успешная демонстрация MVP и защита перед экспертами |
| **Sprint 7 — Рецензирование проектов** | 10 | - Анализ проектов других команд<br>- Подготовка обратной связи<br>- Актуализация документации для будущих команд | Цель: Документация и рекомендации подготовлены |

---

## 3. Зависимости задач

- **Sprint 2** зависит от Sprint 1 (требуется документация и Use Cases).  
- **Sprint 3** зависит от Sprint 2 (архитектура и структура БД).  
- **Sprint 4** зависит от Sprint 3 (MVP).  
- **Sprint 5** зависит от Sprint 4 (production-ready инфраструктура).  
- **Sprint 6** зависит от Sprint 5 (готовность системы для демонстрации).  
- **Sprint 7** может проводиться после Sprint 6, но не критична для MVP.

## 5. KPI по спринтам (текущее состояние)

| Sprint 6 | Цель: Успешная демонстрация продукта, презентация архитектуры и метрик |
| Sprint 7 | Цель: Документация и рекомендации подготовлены, обратная связь по проектам других команд |

## 6. Риски и митигация

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Нестабильность внешних API | Средняя | Высокое | Кэширование, fallback на локальную БД |
| Задержка генерации плана (>5 сек) | Средняя | Среднее | Асинхронные очереди, оптимизация алгоритмов |
| Ошибки AI-модуля | Средняя | Среднее | Юнит-тесты, контейнеризация |
| Проблемы с экспортом | Низкая | Среднее | Юнит-тесты генерации файлов |
| Нехватка ресурсов команды | Средняя | Высокое | Пересмотр приоритетов, упрощение MVP |
| Утечка данных | Низкая | Критическое | HTTPS, JWT, шифрование паролей |
| Перерасход бюджета | Средняя | Среднее | Контроль спринтов, использование open-source |
