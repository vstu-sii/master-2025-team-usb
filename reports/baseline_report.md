# Отчет по оценке качества Baseline-модели (AI Meal Planner)

**Дата:** 15.10.2025
**Версия модели:** `gpt-4o-mini` (baseline)
**Автор:** AI Engineer

## 1. Краткие выводы (Executive Summary)

Первая `baseline`-модель успешно достигла своей основной цели: она продемонстрировала способность генерировать полные, структурированные и логически корректные планы питания в строгом соответствии с заданными инструкциями. Модель `gpt-4o-mini` показала себя как надежный инструмент для данной задачи, обеспечивая стабильный JSON-вывод и адекватное качество контента. Текущая реализация является прочной основой для дальнейшей итеративной разработки и перехода к количественной оценке по метрикам.

## 2. Цели и задачи этапа

Основной целью данного этапа было не достижение максимального качества, а создание **простейшей работающей end-to-end системы**, которая решает следующие задачи:
- **Техническая реализуемость:** Доказать, что LLM способна генерировать данные в требуемом сложном формате.
- **Интеграция:** Создать рабочий класс `BaselineModel`, который инкапсулирует логику вызова LLM.
- **Наблюдаемость (Observability):** Интегрировать систему с Langfuse с первого шага для обеспечения полной прозрачности и отладки.

## 3. Архитектура и реализация

- **Модель:** В качестве основной модели была выбрана **`gpt-4o-mini`** как оптимальное решение, сочетающее высокую скорость, низкую стоимость и отличное качество следования инструкциям для структурированных задач.
- **Логика:** Вся логика генерации инкапсулирована в классе `BaselineModel`. Этот класс отвечает за форматирование промпта, вызов API OpenAI и базовую обработку ответа.
- **Обработка вывода:** Особое внимание уделено постобработке ответа от LLM. Код включает логику для очистки вывода от стандартных Markdown-блоков (`` `json ...` ``), что значительно повышает надежность парсинга JSON и стабильность API.
- **Мониторинг:** Каждый вызов генерации обернут в декоратор `@observe` от **Langfuse**. Это гарантирует, что каждый промпт, ответ, задержка и стоимость автоматически логируются, что является критически важным для последующего анализа и отладки.

## 4. Качественный анализ результатов

На данном этапе оценка проводилась путем ручного анализа нескольких десятков генераций по разным пользовательским запросам.

### 4.1. Следование инструкциям и качество генерации

Модель продемонстрировала высокий уровень управляемости и предсказуемости.

- **Соблюдение формата JSON:**
  **Результат:** **Высокий.** Модель стабильно возвращает ответ в формате JSON. Встроенная логика очистки эффективно справляется со случаями, когда модель оборачивает JSON в Markdown, обеспечивая почти 100% успешный парсинг. Это позволяет гарантировать стабильный API-контракт для Fullstack-инженера.

- **Корректность расчетов КБЖУ:**
  **Результат:** **Высокий.** Модель корректно выполняет инструкцию по подсчету итоговой суточной калорийности и БЖУ, суммируя значения из отдельных приемов пищи. Ошибки в расчетах в ходе ручной проверки не были выявлены, что подтверждает ее базовые математические способности в контексте задачи.

- **Логичность и релевантность контента:**
  **Результат:** **Высокий.** Сгенерированные планы питания являются логически состоятельными:
    - **Типы блюд:** Модель правильно соотносит типы блюд с приемами пищи (например, каши и омлеты на завтрак; супы и горячие блюда на обед; легкие салаты и белковые блюда на ужин).
    - **Разнообразие:** Рацион в рамках недели достаточно разнообразен и не содержит повторяющихся изо дня в день блюд.
    - **Адекватность рецептов:** Предложенные рецепты просты, понятны и не содержат "галлюцинаций" (несуществующих или экзотических ингредиентов).

**Вывод по разделу:** `baseline`-модель является не просто генератором текста, а предсказуемым и управляемым компонентом системы, который точно выполняет поставленные перед ним задачи.
